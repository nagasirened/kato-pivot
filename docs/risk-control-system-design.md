## 1. 问题陈述

电商平台需要一套**可配置、可运营**的风控系统，覆盖用户全生命周期六大环节（注册/登录/营销/下单/支付/退款），支持**动态 Groovy 脚本规则**，规则变更后可通过**脚本单元测试**验证正确性，系统作为独立服务部署。

---

## 2. 设计目标

- **运营平台**：前端 Vue3，策略运营和风控专员共用，风控专员看案件，策略运营配规则
- **规则引擎**：配置规则（页面可视化）+ Groovy 动态脚本（复杂逻辑），两者叠加
- **规则验证**：Groovy 脚本单元测试 — 给模拟输入，验证输出
- **实时同步**：下单/支付等环节毫秒级同步返回决策
- **热更新**：Kafka 消息驱动规则热reload，不重启服务

## 4. 模块职责

### 4.1 kato-risk-client（SDK）

**职责**：业务系统引入的轻量客户端，通过 gRPC 调用风控 Server，提供简洁 API。

```java
// 业务系统调用示例
RiskResponse response = riskClient.check("ORDER", OrderContext.builder()
    .userId("u123")
    .deviceId("d456")
    .ip("1.2.3.4")
    .orderAmount(new BigDecimal("299.00"))
    .shippingAddress("上海市浦东新区...")
    .build());

if (response.getAction() == RiskAction.BLOCK) {
    throw new BusinessException("订单疑似套现，请联系客服");
}
```

**设计要点**：
- 业务方只关心 `RiskRequest` → `RiskResponse`，不接触 Groovy / 规则引擎细节
- 内置 Caffeine 本地缓存 + Redis 分布式缓存（规则结果缓存）
- Resilience4j 熔断，规则引擎不可用时默认放行（fail-open）
- **通过 gRPC 调用风控 Server**，业务系统引入 `kato-risk-client` 依赖即可接入
- **幂等设计**：业务系统 Retry 前需缓存 request_id 结果，风控 server 按 request_id 去重后返回缓存结果
- **容错设计**：BusinessDataProvider 超时 → Retry 2x → 仍超时则返回 `RiskResponse(action=PASS, reasonCode="DATA_PROVIDER_TIMEOUT")` + 企业微信预警，不向上透传异常

**gRPC 接口定义（风控 Server 提供）**：
```java
@FeignClient(name = "kato-risk-server", url = "${risk.server.url}")
public interface RiskFeignClient {

    @PostMapping("/risk/check")
    RiskResponse check(@RequestBody RiskRequest request);

    @PostMapping("/risk/check/groovy")
    GroovyTestResult testGroovyScript(@RequestBody GroovyTestRequest request);
}
```

**业务数据查询 Feign 接口（风控 Client 调用业务方）**：
```java
// 定义在 kato-risk-client 中，业务方实现该接口并注册为 Bean
@FeignClient(name = "business-data-provider")
public interface BusinessDataProvider {

    @GetMapping("/internal/user/{userId}/recent-orders")
    List<OrderInfo> getRecentOrders(@PathVariable("userId") String userId,
                                    @RequestParam("days") int days);

    @GetMapping("/internal/user/{userId}/addresses")
    List<AddressInfo> getUserAddresses(@PathVariable("userId") String userId);

    @GetMapping("/internal/user/{userId}/refund-records")
    List<RefundRecord> getRefundRecords(@PathVariable("userId") String userId,
                                         @RequestParam("days") int days);
}
```
> 业务方只需实现 `BusinessDataProvider` 接口并暴露为 Spring Bean，风控 Client 自动调用。保持接口定义在 `kato-risk-client`，逻辑完整性在业务方。

### 4.2 kato-risk-server（规则执行服务）

#### 4.2.1 规则执行引擎

**输入**：`RiskRequest`（用户 ID / 设备指纹 / IP / 行为数据 / 上下文）

**输出**：`RiskResponse`（action: PASS / REVIEW / BLOCK + reasonCodes[] + score）

**执行流程**：
```
收到请求
  → scene 参数白名单校验（REGISTER/LOGIN/MARKETING/ORDER/PAYMENT/REFUND），非法直接返回 400
  → 规则匹配（按环节 + 场景标签）
  → 执行配置规则（条件表达式）
  → 执行 Groovy 脚本（如有）
  → 风险分数加权计算
  → 返回决策
```

**规则匹配**：
- 每个环节（REGISTER / LOGIN / MARKETING / ORDER / PAYMENT / REFUND）独立的规则集
- 规则有优先级（order 字段），从上到下执行
- 一旦返回 BLOCK，后续规则不再执行

#### 4.2.2 规则分类

| 类型 | 说明 | 示例 |
|------|------|------|
| 配置规则 | SpEL 表达式字符串（页面可视化配置），存 `risk_rule.content` | 同设备注册次数 > 3 → BLOCK |
| 配置规则安全 | SpEL 白名单校验：仅允许 `==、!=、>、<、>=、<=、&&、||`，禁止 `#this、T()、execute()` 等危险操作 |
| Groovy 脚本 | 整段 Groovy 脚本存 MySQL，加载本地缓存后执行 | 地址相似度聚类、购买行为时序检测 |
| Groovy 脚本 | 复杂逻辑，算法，时序分析 | 地址相似度聚类、购买行为时序检测 |

#### 4.2.3 Groovy 脚本执行

**安全隔离**：Groovy Shell 禁止文件系统操作 / 网络操作 / 反射，只能访问提供的 `RiskCheckContext` 对象。

**执行保护**：`ExecutorService.submit() + Future.get(500ms, TimeUnit.MILLISECONDS)`，超时强制中断线程并归还线程池，不等待 finally 清理。使用 `Executors.newCachedThreadPool()`（无上限），避免线程池耗尽。

**脚本结构**：
```groovy
// 固定入参：ctx  // RiskCheckContext
// 固定返回：Map<String, Object>（包含 action, score, reasonCode, message）

// 示例：地址聚类检测
def addresses = ctx.orderContext.shippingAddress
def recentOrders = ctx.recentOrders // 从上下文获取近期订单
def clusterScore = calculateAddressCluster(addresses, recentOrders)

return [
    action: clusterScore > 0.8 ? "BLOCK" : "PASS",
    score: clusterScore,
    reasonCode: "ADDR_CLUSTER",
    message: "收货地址集中度异常"
]
```

**脚本管理**：
- **存储**：整段 Groovy 脚本文本存 MySQL `risk_rule.content`，每次编辑产生新版本，不影响在线版本
- **加载**：启动时 / Kafka 收到更新事件 → 从 MySQL 读取脚本 → 编译为本地缓存的 Groovy Class
- **缓存失效**：Kafka 收到 rule-updated 事件 → 清除 Caffeine 本地缓存中对应 ruleId 的旧版本脚本 + 清除 Redis 分布式缓存（client 侧）
- **A/B 路由**：请求入口根据 `ab_group` 字段匹配流量（例：ab_group="10%" → 10% 请求路由到新版本）
- **安全审核**：上线前静态扫描脚本 AST，禁止 File / Network / Reflection 操作，审核通过才允许保存
- 上线前必须通过单元测试（见 4.3.2）
- 测试环境验证 → 灰度规则 → 全量上线

#### 4.2.4 热更新机制

```
运营在 admin 修改规则
  → 写入 MySQL（版本+状态）
  → Kafka Producer 发送 "rule-updated" 事件（含 ruleId + version）
  → Server Consumer 接收，重新加载指定规则
  → 清除 Caffeine 本地缓存
  → 下一请求使用新规则
```

### 4.3 kato-risk-admin（运营平台 Vue3）

#### 4.3.1 策略运营工作台

**规则管理**：
- 规则列表（按环节筛选，支持启/停），环节用颜色标签区分
- 每条规则显示"上次更新时间"，有"刷新缓存"按钮（注册=蓝/登录=绿/营销=橙/下单=红/支付=紫/退款=灰）
- 规则新建/编辑（配置规则表单 或 Groovy 脚本编辑器）
- 规则版本历史（可回滚）
- 规则变更审计日志（谁在什么时候改了什么内容）
- **动态规则 A/B 配置**：运营可设置灰度流量比例，独立 Topic `risk-rule-update` 推送 A/B 实验配置

**Groovy 脚本编辑器**：
- 左侧：代码编辑器（语法高亮，Groovy 语言支持）
- 右侧：单元测试面板，配置输入 Mock 数据，执行后显示输出
- 左下角：运行时输出面板（类似 Jupyter，展示每一步中间变量）
- 底部：执行结果（action / score / reasonCode / message / 执行耗时）
- 不通过测试不允许保存上线

#### 4.3.2 脚本单元测试

**测试用例管理**：
```json
{
  "scriptId": "addr_cluster_v2",
  "testCases": [
    {
      "name": "正常地址",
      "input": {
        "shippingAddress": "上海市浦东新区XX路1号",
        "recentOrders": [...]
      },
      "expected": {
        "action": "PASS",
        "score": 0.1
      }
    },
    {
      "name": "地址集中度异常",
      "input": {
        "shippingAddress": "上海市某区某镇某村",
        "recentOrders": [
          {"addr": "上海市某区某镇某村", "time": "2026-05-01"},
          {"addr": "上海市某区某镇某村", "time": "2026-05-15"}

      }
    }

```

**测试执行**：服务端执行，返回每个用例的执行结果，标记 PASS / FAIL。

#### 4.3.3 风控专员案件台

**告警列表**：
- 筛选条件：环节 / 时间范围 / action类型 / 处理状态
- 列表字段：用户ID / 环节 / 触发规则 / 风险分数（颜色热力图：红=高风险）/ 时间 / 状态
- 按 risk_score 排序，高风险优先展示
- 支持批量操作（批量放行、批量验证）

**案件详情**：
- 用户信息（ID / 设备指纹 / 注册时间 / 历史行为摘要）
- 当前请求上下文（IP / 地址 / 金额 等环节相关数据）
- 规则命中明细（触发了哪些规则，分数贡献）
- 处置操作（拦截/验证/放行 + 备注）
- 操作日志（谁在什么时间做了什么操作）

### 4.4 数据模型

#### 4.4.1 规则配置表

```sql
CREATE TABLE risk_rule (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    scene VARCHAR(50) NOT NULL,        -- REGISTER/LOGIN/MARKETING/ORDER/PAYMENT/REFUND
    rule_type VARCHAR(20) NOT NULL,    -- CONFIG/GROOVY
    content TEXT,                       -- 配置规则JSON 或 Groovy脚本
    priority INT DEFAULT 0,
    enabled TINYINT(1) DEFAULT 1,
    version INT DEFAULT 1,
    ab_group VARCHAR(20),             -- A/B实验分组（如 "10%" 表示10%流量走此规则）
    created_by VARCHAR(64),
    created_at DATETIME,
    updated_at DATETIME,
    INDEX idx_scene_enabled (scene, enabled, priority)
);
```

#### 4.4.2 案件表

```sql
CREATE TABLE risk_case (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(64) NOT NULL,
    scene VARCHAR(50) NOT NULL,
    request_id VARCHAR(64) NOT NULL,
    action VARCHAR(20) NOT NULL,       -- PASS/REVIEW/BLOCK
    risk_score DECIMAL(5,4),
    reason_codes TEXT,
    request_context TEXT,              -- JSON
    status VARCHAR(20) DEFAULT 'PENDING',
    handler VARCHAR(64),
    handle_note TEXT,
    handle_time DATETIME,
    created_at DATETIME,
    INDEX idx_scene_status_time (scene, status, created_at)
);
```

#### 4.4.4 规则变更审计表

```sql
CREATE TABLE risk_rule_audit (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    rule_id BIGINT NOT NULL,
    operation VARCHAR(20) NOT NULL,    -- CREATE/UPDATE/DELETE/ENABLE/DISABLE
    operator VARCHAR(64) NOT NULL,
    old_content TEXT,
    new_content TEXT,
    operate_at DATETIME
);
```

#### 4.4.3 拒绝日志表（风控拒绝必写）

```sql
CREATE TABLE risk_reject_log (
    -- 拒绝日志高频写入，MySQL 连接失败时降级写入内存 buffer，定时重试，不丢弃
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_id VARCHAR(64) NOT NULL,
    user_id VARCHAR(64),
    scene VARCHAR(50) NOT NULL,
    action VARCHAR(20) NOT NULL,       -- PASS/REVIEW/BLOCK
    risk_score DECIMAL(5,4),
    hit_rules TEXT,                    -- 命中的规则列表JSON
    reason_codes TEXT,
    request_context TEXT,             -- 请求上下文JSON
    rule_type VARCHAR(20),            -- CONFIG/GROOVY
    script_version VARCHAR(20),       -- Groovy脚本版本（仅GROOVY类型）
    ab_group VARCHAR(20),            -- A/B实验分组（仅动态规则）
    created_at DATETIME,
    UNIQUE INDEX idx_request_id (request_id),
    INDEX idx_user_time (user_id, created_at),
    INDEX idx_scene_time (scene, created_at)
) COMMENT='高频写入，MySQL失败时降级内存buffer，定时重试';

```

## 5. 各环节设计

| 环节 | 配置规则示例 | Groovy 脚本场景 |
|------|------------|--------------|
| **注册** | 同IP注册次数>3→BLOCK；同设备注册次数>2→验证码 | 虚假批量注册设备指纹相似度检测 |
| **登录** | 异地登录→验证码；异地+新设备→风控审 | 撞库行为检测（失败次数聚集在短时窗） |
| **营销** | 优惠券领取频率>5次/小时→拒绝；同设备多账号领取→拒绝 | 薅羊毛行为时序分析（领取→转让→使用） |
| **下单** | 同地址/同收货人聚集→人工审；夜间高额→验证 | 地址聚类算法；购买行为异常检测 |
| **支付** | 常用卡+常用地址→低风险；新卡+新地址→验证 | 盗卡检测（卡信息与历史偏离度） |
| **退款** | 退款频率>3次/月→审核；凭证异常→审核 | 恶意退款时序模式识别 |

## 6. Open Questions（全部已确认 ✅）

1. ✅ **Q1 已确认 — 业务接口查询（gRPC）**：规则执行时通过 gRPC 回调用业务方接口获取用户历史行为数据，`BusinessDataProvider` 接口定义在 `kato-risk-client`，业务方实现并注册为 Bean 即可，风控不建独立数据仓库。

2. ✅ **Q2 已确认 — 规则效果监控（非回测）**：
   - 不做自动历史回测
   - 运行时统计**动态规则**和**非动态规则**的通过率/拒绝率
   - 动态规则（Groovy）支持 **A/B 配置**（灰度比例可调）
   - 风控拒绝时，**日志必须落表**（写 `risk_reject_log` 表）

3. ✅ **Q3 已确认 — 独立 Kafka Topic**：新建 `risk-rule-update` Topic，不复用 `sensitive-word-update`。

4. ✅ **Q4 已确认 — 业务自行处理**：风控只返回 PASS/REVIEW/BLOCK 和 reasonCode，业务系统自行执行处罚。

## 8. 实施路径

**Phase 1（2-3周）✅ 优先级最高**
- `kato-risk-server` 核心模块：规则引擎 + 规则配置表 + 脚本表 + 案件表 + 拒绝日志表
- `kato-risk-client` SDK：gRPC 调用风控 Server + BusinessDataProvider 接口定义
- **BusinessDataProvider 超时策略**：重试 2 次 → 仍超时则抛异常 → 触发企业微信机器人预警
- **Groovy 安全审核机制**：上线前静态扫描（检查文件/网络/反射等危险操作）
- **Groovy 脚本存储**：整段脚本存 MySQL，加载到本地缓存执行
- 第一个环节（注册或登录）的规则跑通

**Phase 2（2-3周）**：核心功能
- 配置规则 CRUD + 执行
- Groovy 脚本管理 + 执行
- Kafka 热更新
- 注册/登录/营销三个环节规则

**Phase 3（2-3周）**：运营平台 Vue3
- 策略运营工作台（规则管理 + 脚本编辑器 + 单元测试 + 规则统计）
- 风控专员案件台（告警列表 + 案件详情 + 处置操作）
- 企业微信预警接入（超时告警 + 规则拒绝告警）

**Phase 4（2周）**：下单/支付/退款 + 全链路联调
- 剩余三个环节规则
- 端到端联调
- 性能压测

## 9. 风险与注意事项

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| **RiskCheckContext 内存压力** | 历史订单数据多时（如高活跃用户数百条），RiskCheckContext 对象大，高频调用可能触发 Full GC | BusinessDataProvider 限制返回量：最多查最近 30 天 / 不超过 100 条记录 |
| **scene 参数注入** | 伪造 scene 绕过环节风控 | scene 白名单校验，非白名单值直接返回 400 |
| **Groovy 执行死循环** | 恶意或低质脚本含无限循环，阻塞线程池 | 执行 timeout 500ms，超时强制中断 |
| **Groovy 缓存不一致** | 服务重启后本地 Groovy Class 缓存丢失，Kafka 推送前短暂真空期 | 启动时全量加载所有已上线 Groovy 脚本到缓存 |
| **拒绝日志写入热点** | risk_reject_log 高频写入，无索引时查询慢 | 已加 idx_user_time 和 idx_scene_time 复合索引 |
| **企业微信预警风暴** | BusinessDataProvider 超时率升高时，预警消息刷屏 | 需业务方配合优化查询性能；预警加频次限制（如同一接口 5 分钟内不重复告警） |
